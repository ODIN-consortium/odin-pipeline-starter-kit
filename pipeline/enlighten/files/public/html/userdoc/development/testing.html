Testing Guide¶

This guide covers testing strategies and procedures for OpenEnlighten.

Testing Philosophy¶

OpenEnlighten uses a multi-layered testing approach:

  • Unit Tests: Test individual components in isolation

  • Integration Tests: Test component interactions

  • End-to-End Tests: Test complete user workflows

  • API Tests: Test FastAPI endpoints and contracts

Backend Testing¶

Test Structure:

tests/
├── test_app_core.py        # Core functionality tests
├── test_app_services.py    # Service layer tests
├── test_colormaps.py      # Colormap functionality
├── test_database.py       # Database operations
├── test_plugin_manager.py # Plugin system tests
└── conftest.py           # Shared test fixtures

Running Tests:

# All tests
python -m pytest tests/ -v

# Specific test file
python -m pytest tests/test_plugin_manager.py -v

# With coverage
python -m pytest tests/ -v --cov=app --cov-report=html

Test Configuration:

Tests use the shared configuration system with test-specific overrides:

# conftest.py example
@pytest.fixture
def test_config():
    config = ServerConfig()
    config.plugins.enabled = []  # Disable plugins for testing
    return config

Writing Unit Tests:

import pytest
from app.models.server_config import ServerConfig

def test_server_config_defaults():
    """Test that ServerConfig has proper defaults."""
    config = ServerConfig()
    assert config.server.host == "127.0.0.1"
    assert config.server.port == 8080
    assert config.server.debug is False

@pytest.mark.asyncio
async def test_async_endpoint():
    """Test async FastAPI endpoint."""
    # Async test example
    response = await client.get("/api/status")
    assert response.status_code == 200

Frontend Testing¶

Test Types:

  • Component Tests: Angular component behavior

  • Service Tests: Angular service functionality

  • E2E Tests: User interaction flows

  • Visual Tests: UI rendering validation

Running Frontend Tests:

# Unit tests
npm test

# E2E tests (requires running servers)
npm run test:e2e

# With coverage
npm run test:coverage

Component Testing Example:

describe('MapComponent', () => {
  let component: MapComponent;
  let fixture: ComponentFixture<MapComponent>;

  beforeEach(() => {
    TestBed.configureTestingModule({
      declarations: [MapComponent],
      imports: [HttpClientTestingModule]
    });
    fixture = TestBed.createComponent(MapComponent);
    component = fixture.componentInstance;
  });

  it('should initialize Cesium viewer', () => {
    component.ngOnInit();
    expect(component.viewer).toBeTruthy();
  });
});

API Testing¶

Testing FastAPI Endpoints:

from fastapi.testclient import TestClient
from app.main import app

client = TestClient(app)

def test_get_status():
    """Test status endpoint."""
    response = client.get("/api/status")
    assert response.status_code == 200
    data = response.json()
    assert "status" in data

def test_plugin_endpoints():
    """Test plugin management endpoints."""
    # Test plugin listing
    response = client.get("/api/plugins")
    assert response.status_code == 200

    # Test plugin info
    response = client.get("/api/plugins/obspy")
    assert response.status_code in [200, 404]

Configuration Testing¶

Testing YAML Configurations:

def test_client_config_loading():
    """Test loading client configuration from YAML."""
    config = ClientConfig.from_yaml_file("config/client_config.yaml")
    assert config.cesium.terrain.enabled is True
    assert len(config.cesium.layers) > 0

def test_config_validation():
    """Test configuration validation."""
    with pytest.raises(ValidationError):
        ClientConfig(cesium={"invalid": "config"})

Plugin Testing¶

Testing Plugin System:

def test_plugin_discovery():
    """Test plugin discovery mechanism."""
    manager = PluginManager()
    plugins = manager.discover_plugins()
    assert len(plugins) >= 0

def test_plugin_loading():
    """Test plugin loading."""
    manager = PluginManager()
    success = manager.load_plugin("obspy_plugin")
    assert success in [True, False]  # May not be available

Mock Plugin for Testing:

class MockPlugin:
    """Mock plugin for testing."""

    def __init__(self):
        self.name = "mock_plugin"
        self.version = "1.0.0"

    def process_data(self, data):
        return {"processed": True, "data": data}

Test Data Management¶

Test Data Structure:

tests/
├── fixtures/
│   ├── test_data.json      # Sample JSON data
│   ├── sample_config.yaml  # Test configuration
│   └── mock_responses/     # API response mocks
└── conftest.py

Loading Test Data:

import json
from pathlib import Path

@pytest.fixture
def sample_data():
    """Load sample test data."""
    test_dir = Path(__file__).parent
    data_file = test_dir / "fixtures" / "test_data.json"
    with open(data_file) as f:
        return json.load(f)

Test Best Practices¶

General Guidelines:

  • Write tests before fixing bugs (TDD approach)

  • Keep tests simple and focused

  • Use descriptive test names

  • Mock external dependencies

  • Test both success and failure cases

  • Maintain test data separately

Performance Considerations:

  • Use fixtures for expensive setup operations

  • Mock file system operations

  • Avoid network calls in unit tests

  • Use pytest markers to categorize tests

Test Organization:

# Mark slow tests
@pytest.mark.slow
def test_large_data_processing():
    pass

# Mark integration tests
@pytest.mark.integration
def test_api_integration():
    pass

# Run specific test categories
# pytest -m "not slow"  # Skip slow tests
# pytest -m integration  # Only integration tests

Debugging Tests¶

Common Issues:

  • Import Errors: Check PYTHONPATH and module structure

  • Fixture Errors: Verify fixture scope and dependencies

  • Async Test Issues: Use @pytest.mark.asyncio properly

  • Mock Problems: Ensure mocks are applied correctly

Debugging Commands:

# Run with detailed output
python -m pytest tests/ -v -s

# Drop into debugger on failure
python -m pytest tests/ --pdb

# Run specific test with debugging
python -m pytest tests/test_plugin_manager.py::test_specific_function -v -s
