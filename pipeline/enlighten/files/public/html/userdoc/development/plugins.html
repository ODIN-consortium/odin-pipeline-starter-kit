Plugin System¶

This guide covers the plugin system architecture used in OpenEnlighten to extend functionality, particularly for seismic data integration.

Overview¶

OpenEnlighten uses a modular plugin system to extend functionality beyond the core application. The primary use case is integrating seismic data through ObsPy, but the architecture supports various plugin types.

Architecture¶

Plugin Loading Process¶

  1. Configuration: Server reads server_config.yaml on startup

  2. Initialization: Enabled plugins are initialized with their configurations

  3. Registration: Plugin data becomes available through API endpoints

  4. Integration: Frontend can request plugin data via HTTP calls

Plugin Configuration¶

Plugins are configured in server_config.yaml:

plugins:
  obspy_fdsn:
    enabled: true
    config:
      base_url: "http://service.iris.edu"
      timeout: 30
      max_results: 1000

Available Plugins¶

ObsPy FDSN Plugin¶

Purpose: Provides seismic station data via FDSN web services

Data Source: IRIS earthquake data center and other FDSN-compatible services

Configuration:

plugins:
  obspy_fdsn:
    enabled: true
    config:
      base_url: "http://service.iris.edu"
      timeout: 30
      max_results: 1000
      network_filter: "*"
      station_filter: "*"

Features:

  • Automatic loading when shared config is used

  • FDSN web service integration

  • Station metadata retrieval

  • Real-time data access

  • Geographic filtering capabilities

API Integration: Available through FastAPI routes at /api/plugins/obspy_fdsn/

Plugin Development¶

Adding New Plugins¶

To create a new plugin:

  1. Create Plugin Directory and Module:

    Create a new directory for your plugin with the required structure:

    my_plugin/
├── pyproject.toml      # Dependencies and metadata
├── my_plugin/
│   ├── __init__.py
│   └── plugin.py       # Main plugin implementation
└── README.md

  2. Create Plugin Class:

    # my_plugin/my_plugin/plugin.py
import logging
from typing import List
import pandas as pd
from fastapi import APIRouter

logger = logging.getLogger(__name__)

class MyPlugin:
    def __init__(self, name: str, **kwargs):
        self.plugin_name = name
        # Initialize with any extra configuration
        self.config = kwargs

    def get_dataset_descriptions(self) -> List:
        """Return list of datasets this plugin provides"""
        return [
            {
                "id": self.plugin_name,
                "name": "My Plugin Dataset",
                "value": "my_data"
            }
        ]

    def get_dataset(self, chunk: str) -> pd.DataFrame:
        """Retrieve data based on chunk parameters"""
        # Your data retrieval logic here
        return pd.DataFrame({"example": [1, 2, 3]})

    def get_router(self):
        """Optional: provide custom API routes"""
        router = APIRouter()

        @router.get("/info")
        async def plugin_info():
            return {"name": self.plugin_name, "version": "1.0.0"}

        return router

def setup(name: str, **kwargs):
    """Required setup function for the plugin system"""
    logger.info(f"Setting up {name} plugin")
    return MyPlugin(name, **kwargs)

  3. Add Configuration:

    Add configuration section to server_config.yaml:

    plugins:
  - name: "my_plugin"
    type: "pluggy"
    path: "../my_plugin"
    module: "my_plugin.plugin"
    # Additional plugin-specific configuration
    extra:
      api_key: "your_api_key"
      endpoint: "https://api.example.com"

  4. Implement API Routes (Optional):

    If your plugin needs custom routes, implement a get_router() method in your plugin:

    # my_plugin/plugin.py
from fastapi import APIRouter

class MyPlugin:
    def get_router(self):
        router = APIRouter()

        @router.get("/data")
        async def get_my_plugin_data():
            return self.get_data()

        return router

    The plugin manager will automatically register these routes at /plugins/my_plugin/.

Plugin Interface¶

All plugins should inherit from BasePlugin and implement required methods:

from abc import ABC, abstractmethod

class BasePlugin(ABC):
    def __init__(self, config):
        self.config = config

    @abstractmethod
    def initialize(self):
        """Initialize plugin with configuration"""
        pass

    @abstractmethod
    def get_data(self, **kwargs):
        """Retrieve plugin data"""
        pass

    def is_available(self):
        """Check if plugin is available"""
        return True

Dependencies¶

Core Dependencies:

  • ObsPy: For seismic data processing

  • Requests: For web service calls

  • Pydantic: For configuration validation

  • FastAPI: For API route integration

Plugin-Specific Dependencies:

Plugin dependencies are automatically managed through pyproject.toml. The plugin manager will automatically detect and install missing dependencies when loading plugins:

[project]
name = "my_plugin"
version = "0.1.0"
dependencies = [
    "obspy>=1.4.0",
    "requests>=2.28.0",
    "numpy>=1.21.0",
    "pandas>=1.3.0",
    "fastapi>=0.116.1"
]

Automatic Installation: When a plugin is loaded, the system will:

  1. Parse the plugin’s pyproject.toml file

  2. Check if all dependencies are installed

  3. Automatically install any missing dependencies using pip

  4. Load the plugin once all dependencies are satisfied

This eliminates the need for manual dependency installation when adding new plugins.

API Integration¶

Frontend Integration¶

The Angular frontend can consume plugin data through HTTP calls:

// Angular service for plugin data
@Injectable()
export class PluginService {

  getObsPyStations(): Observable<StationData[]> {
    return this.http.get<StationData[]>('/api/plugins/obspy_fdsn/stations');
  }

  getSeismicData(params: SeismicParams): Observable<SeismicData> {
    return this.http.get<SeismicData>('/api/plugins/obspy_fdsn/data', { params });
  }
}

Cesium Visualization¶

Plugin data can be visualized in Cesium:

// Display seismic stations on Cesium globe
displayStations(stations: StationData[]) {
  stations.forEach(station => {
    this.viewer.entities.add({
      position: Cesium.Cartesian3.fromDegrees(
        station.longitude,
        station.latitude,
        station.elevation
      ),
      point: {
        pixelSize: 8,
        color: Cesium.Color.YELLOW,
        outlineColor: Cesium.Color.BLACK,
        outlineWidth: 2
      },
      label: {
        text: station.code,
        font: '12pt sans-serif',
        pixelOffset: new Cesium.Cartesian2(0, -40)
      }
    });
  });
}

Configuration Management¶

Configuration Validation¶

Plugin configurations are validated using Pydantic models:

from pydantic import BaseModel, validator

class ObsPyPluginConfig(BaseModel):
    base_url: str = "http://service.iris.edu"
    timeout: int = 30
    max_results: int = 1000

    @validator('base_url')
    def validate_url(cls, v):
        if not v.startswith(('http://', 'https://')):
            raise ValueError('base_url must be a valid HTTP/HTTPS URL')
        return v

Environment Variables¶

Sensitive configuration can use environment variables:

plugins:
  my_plugin:
    enabled: true
    config:
      api_key: "${MY_PLUGIN_API_KEY}"
      endpoint: "${MY_PLUGIN_ENDPOINT:https://default.example.com}"

Troubleshooting¶

Common Issues¶

Plugin not loading:

  • Check server_config.yaml syntax and indentation

  • Verify plugin is enabled in configuration

  • Check server startup logs for error messages

No plugin data:

  • Verify plugin is enabled and properly configured

  • Check plugin dependencies are installed

  • Test plugin configuration with minimal setup

FDSN errors:

  • Check network connectivity to FDSN services

  • Verify service URLs and availability

  • Check for service-specific requirements (authentication, etc.)

Configuration errors:

  • Validate YAML structure and required fields

  • Check for missing or invalid configuration values

  • Use configuration validation endpoints for testing

Debugging¶

Enable Debug Logging:

import logging
logging.getLogger('app.plugins').setLevel(logging.DEBUG)

Plugin Status Endpoint:

Check plugin status through API:

curl http://localhost:8081/api/plugins/status

Configuration Validation:

Test configuration before deployment:

from app.core.config import validate_plugin_config
validate_plugin_config(config_dict)

Performance Considerations¶

Data Caching: Implement caching for frequently accessed data:

from functools import lru_cache

class MyPlugin(BasePlugin):
    @lru_cache(maxsize=100)
    def get_cached_data(self, query_params):
        return self.fetch_data(query_params)

Async Operations: Use async operations for I/O-bound tasks:

import asyncio
import aiohttp

async def fetch_async_data(self, url):
    async with aiohttp.ClientSession() as session:
        async with session.get(url) as response:
            return await response.json()

Resource Management: Properly manage external connections and resources.

Security Considerations¶

  • API Keys: Store sensitive data in environment variables

  • Input Validation: Validate all plugin inputs and parameters

  • Rate Limiting: Implement rate limiting for external API calls

  • Error Handling: Avoid exposing internal details in error messages
